# Oways Tech — أويس تك

مشروع مستقل لخدمات رقمية عربية RTL. Node.js 22+، وMySQL 8.0.16+.

## تشغيل النسخة المرتبطة بالخادم في VS Code / Git Bash

```bash
git pull origin main
npm install
cp .env.example .env
```

عدّل `.env`: معلومات MySQL، و`OTP_SECRET`، والرقم الدولي للدعم بدون +. توليد السر:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

أنشئ مستخدم MySQL خاصًا بالمشروع. التهيئة الأولى تحتاج صلاحية إنشاء قاعدة وجداول؛ بعد التهيئة استخدم مستخدم تشغيل بصلاحيات SELECT/INSERT/UPDATE/DELETE على `oways_tech` فقط. لا تضع كلمات المرور في GitHub.

```bash
npm run db:init
npm start
```

`db:init` للاستخدام مرة واحدة على قاعدة جديدة فقط، ولا يعيد إنشاء قاعدة موجودة. افتح http://localhost:3000 (نفس القيمة الموجودة في APP_ORIGIN). خادم Node يقدم الموقع وAPI معًا؛ Live Server يعرض التصميم فقط ولا يشغّل الحسابات.

## الدخول وإنشاء أول أدمن

- افتح `/account` وأدخل الاسم ورقم الهاتف بصيغة دولية تبدأ بـ +.
- في وضع التطوير المحلي `OTP_DELIVERY=console` يظهر الرمز في طرفية `npm start` فقط. لا توجد رسالة SMS فعلية في هذا الوضع.
- بعد إنشاء الحساب والتحقق:

```bash
npm run admin:grant -- +963XXXXXXXXX
```

- افتح `/admin` بعد تسجيل الدخول. لا يوجد حساب أدمن أو كلمة مرور افتراضية.
- أضف تصنيفًا ثم خدمة وباقتها الأولى ومتطلباتها وتعليماتها. تظهر في قسم «خدمات المنصة» في الرئيسية. الخدمات القديمة في الرئيسية أمثلة عرض ثابتة؛ معرّفاتها مثل `chatgpt` و`gemini` و`canva` يمكن استعمالها عند إنشاء الخدمات لتفعيل طلبها مباشرة.

## ما يعمل في هذه المرحلة

- طلب OTP والتحقق والجلسات المخزنة في MySQL؛ تسجيل الخروج وإلغاء الجلسة.
- إنشاء تصنيفات وخدمات وباقة أولى مع متطلبات وتعليمات من لوحة الأدمن.
- إنشاء طلب حقيقي بعد التحقق من المتطلبات على الخادم، مع نسخة ثابتة من تفاصيل الخدمة والسعر.
- طلبات العميل وتفاصيلها، ورسائل الدعم المرتبطة بالطلب والباقة.
- مراجعة الأدمن للطلبات وإجابات العميل، وتغيير حالات المراجعة/انتظار العميل/الإلغاء مع رسالة للعميل.
- تحقق الصلاحيات على الخادم؛ منع تغيير الحالة إلى التنفيذ دون دفع مؤكد.

## المراحل غير المنفّذة بعد

تعديل/حذف التصنيفات والخدمات وإضافة باقات أخرى، الطلب متعدد الخدمات، حفظ المسودات، رفع الملفات وإثباتات الدفع، عروض الأسعار وقبولها، تأكيد المدفوعات ورد المبالغ، إجراءات التفعيل، إنشاء الاشتراكات وإتمام الطلب والتجديد، الإشعارات والإعدادات العامة. الجداول جاهزة لكن هذه الواجهات ومساراتها لم تُفعّل بعد. لا يوجد دفع أو تفعيل تلقائي.

## إرسال الرموز في الإنتاج

`OTP_DELIVERY=webhook` يحتاج محول إرسال موثوقًا. يُرسل الخادم HTTPS POST إلى `OTP_DELIVERY_URL` بصيغة `{phone,code,expiresInSeconds}` مع Bearer `OTP_DELIVERY_TOKEN`. يجب أن يرسل المحول رسالة فعلية ويعيد نجاحًا فقط عند قبول الإرسال. اضبط `NODE_ENV=production` و`APP_ORIGIN` إلى رابط HTTPS. وضع console مرفوض في الإنتاج أو عند الاستماع خارج loopback. لا تُرجع API رموزًا إلى المتصفح. تحتاج طبقة reverse proxy مع HTTPS ومحدد معدل مشترك إذا شغّلت أكثر من نسخة للخادم.

## الاختبارات والنشر

```bash
npm test
```

الاختبارات تشمل validation وحماية مسارات HTTP دون قاعدة بيانات. لم يُختبر التكامل الكامل مع MySQL في بيئة التطوير الحالية.

الخادم الحالي يعمل على استضافة Node.js + MySQL. استضافة Sites الحالية تدعم الواجهة الثابتة ولا تشغل هذا الخادم ذي اتصال MySQL TCP؛ لذلك رابط Sites السابق لا يمثل نسخة الحسابات الجديدة. اختيار الاستضافة أو تحويل الخادم إلى نموذج متوافق مع Sites مطلوب قبل نشر هذه النسخة.
